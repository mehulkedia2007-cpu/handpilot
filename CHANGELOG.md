# Changelog

All notable changes to HandPilot are listed here, newest first.

## [Unreleased]

### Phase 5: Agentic AI (LLM with tool calling)
- P5.1: Backend (`server/`). A small Express 5 app on `127.0.0.1:8787` with `GET /health` and `POST /agent`, its own `package.json` (`@anthropic-ai/sdk@0.133.0`, `express@5.3.0`, `dotenv@18.0.7`, all pinned) and `npm run dev`. Settings come from `server/.env` (`ANTHROPIC_API_KEY`, `AGENT_MODEL`, `PORT`, `MAX_STEPS`, `MAX_REQUESTS_PER_MIN`, `REQUEST_TIMEOUT_MS`, plus optional `AGENT_EFFORT`, `AGENT_FALLBACK` and `ALLOWED_ORIGINS`); only `server/.env.example` is committed. There's no built-in model: a missing key or model is listed in `/health`, printed when the server starts, and shown in the page. The key is only read on the server.
- P5.2: Tools (`src/core/tools.js`, re-exported by `server/tools.js`): `move_gripper_to`, `open_gripper`, `close_gripper`, `play_motion`, `set_mode` (MANUAL, HOLD, AUTO, IDLE) and `get_scene`, with `move_gripper_to`'s bounds taken from the workspace box the hand already uses (x −2 to 2, y 0.3 to 2.4, z 1.1 to 2.3, scene units). `checkToolCall` checks and clamps a call; the server and the browser both run it, from the same file.
- P5.3: Agent loop. The browser sends `{command, scene}`; the server asks the model; tool calls go back to the browser, which runs them on the arm and returns the results with the new scene; this repeats until the model answers in words or `MAX_STEPS` (6) is reached. The conversation stays on the server under a random session id, so the step count can't be reset by the page. A new LLM agent mode drives the arm: `src/core/llmArm.js` glides the gripper target to each point (eased, about 1.6 units a second) and waits until forward kinematics says the gripper has arrived (or gives up after a timeout and says so). The system prompt (`server/prompt.js`) describes the arm, the coordinate frame, a pick-and-place recipe and the rules, and asks for one- or two-sentence replies. When the agent finishes it hands back to MANUAL, or to HOLD if the arm still holds a block (an open hand would drop it). Adaptive thinking is left on; with `AGENT_FALLBACK=on` the server uses Anthropic's server-side fallback if the model declines.
- P5.4: Safety. Every number is clamped to the workspace; unknown tools, wrong types (a string where a number belongs, `NaN`, missing fields), bad modes and more than 12 calls in one reply are rejected and the model is told why. `MAX_STEPS` caps model turns per command, `MAX_REQUESTS_PER_MIN` (10) rate-limits commands per address, each model call has a timeout (30 s, one retry) and each browser request one too (45 s). CORS only lets in `localhost` and the GitHub Pages site (the server answers Chrome's local-network preflight), the server listens on `127.0.0.1` only, request bodies are capped at 64 kB, commands at 500 characters and tool results at 4,000. A **Stop** button (or Escape in the box) cancels the request and the arm's current move, tells the server to forget the command and switches to HOLD; holding any command gesture also stops the agent.
- P5.5: UI. An **Ask the arm** box in the agent panel with **Send** (Enter) and **Stop**, a status chip (Not connected, Checking, Online, Agent offline, Not set up, Working) and the agent's final reply. The agent log shows each step: SEE (the command and scene sent, tool results returned), DECIDE (the model's words, rejected calls) and ACT (each tool call with its arguments and anything clamped). The page only contacts the server when you use the box, so the static site makes no extra requests and logs no errors without it; with the server off, the box says "Agent offline" with how to start it, and everything else works as before.
- P5.6 (optional, voice) was skipped.
- Testing: 38 new unit tests (212 in all): tool checks and clamping with malformed and out-of-range calls, the arm executor, a frame-by-frame simulation in which the prompt's recipe really picks up red and stacks red on blue (then green on red), the server loop with a fake model (step limit, rejected calls, result order, size caps, expiry, refusals, stop), config, CORS and the rate limit, and the LLM agent mode. `npm run e2e` gains 17 Phase 5 checks (96 in all) against a fake agent server (`tests/e2e/fake-agent.mjs`: the real loop with a scripted model, no key), including stacking, rejection, Stop, a gesture taking over, and the offline state.
- Docs: README, `docs/ARCHITECTURE.md`, `docs/TESTING.md`, `docs/LEARNING.md` (Phase 5) and `src/core/types.md` updated.

### Phase 4: The robot learns
- P4.1: Record and replay (`src/core/motion.js`). A **Motions** panel with **Record** / **Stop recording** saves the pose of the robot on screen about 30 times a second (whatever the frame rate), for up to a minute, with a red REC timer on the stage. **Play** replays a motion at 0.5×, 1× or 2×, drawing straight lines between samples (linear interpolation, found with a binary search), and switches to the motion's robot first. A new REPLAY agent mode runs the replay and returns to MANUAL when it ends; holding any command gesture interrupts it, but the gesture you were already holding when it started doesn't count. Tests cover interpolation at, between and beyond samples, speeds, the sample rate at 30/60/144 fps, and REPLAY in the agent.
- P4.2: Motion library. Motions are saved in `localStorage` under `handpilot.motions.v1` (apart from settings, so **Reset to defaults** keeps them) and get default names ("Motion 1", ...). Each one can be renamed (Enter saves, Escape cancels; names are tidied and must be unique) or deleted after a confirmation. **Export all** downloads `handpilot-motions.json`; **Import** reads one back. Every motion in a file is checked (`checkMotion`: name, id, robot, sample rate, at least 2 samples with times that go forward, and every joint a finite number) and the import is all or nothing, with a message naming the motion and the problem. Importing a motion that's already there is skipped; clashing names become "Name (2)". If the browser won't save, the motions stay in memory and the note says so. Tests check that an exported file imports back identically, and the error for each kind of bad file.
- P4.3: Normalise landmarks (`normalise` in `src/core/hand.js`): subtract the wrist, divide by the palm's length (wrist to middle knuckle), optionally rotate so that line points up and optionally mirror a left hand, then flatten to 63 numbers (42 with `dropZ`). Rotation is off by default because it would make thumbs up and thumbs down identical. The simulator now produces a made-up 21-point hand from its sliders (`simHandLandmarks`), so the gesture trainer also works without a camera. Tests check that the same shape at a different size, place, tilt (with rotate) or hand (with mirror) gives the same vector, and that different shapes stay far apart.
- P4.4: Gesture trainer (`src/core/knn.js`, `src/core/training.js`, `src/ui/trainer.js`). Type a name and press **Record** (or Enter): a 3-second countdown, then 30 normalised samples over 3 seconds, with a live counter; frames with no hand are skipped, and hand shapes don't fire commands while it records. `KNN({k: 5})` with `add(vector, label)` and `predict(vector) -> {label, confidence, distance}` votes among the 5 nearest examples; it answers "unknown" if fewer than 60% agree or even the nearest example is farther than the **Match distance** (default 0.6 palm lengths, adjustable from 0.2 to 1.5). A live read-out shows what it sees. Each trained gesture can switch mode (MANUAL, HOLD, AUTO, GREET) or play a saved motion; held for ~0.9 s it works like a built-in command and wins over the built-in gestures when the classifier is confident. Left hands are mirrored so they match gestures taught with a right hand. Training data is saved under `handpilot.gestures.v1`, with **Export** / **Import** (`handpilot-gestures.json`, checked like motions; same-name gestures are replaced). Deleting a motion clears any gesture that played it. Tests check that KNN separates synthetic clusters, and that two custom gestures trained on wobbly simulator hands are recognised while untaught shapes stay "unknown".
- P4.5: Accuracy report. **Check accuracy** in the trainer hides 20% of each gesture's samples (a stratified, seeded, shuffled hold-out split, `holdoutSplit`), trains a classifier on the other 80%, and shows the overall score, accuracy per gesture and a confusion table (rows: what you showed; columns: what it answered, including "unknown"), with the right answers in green. Each press tests a different 20%; changing the training data hides the old report. Tests cover the split (sizes per gesture, no overlap, repeatable with a seed, a one-sample gesture) and the accuracy and confusion maths.
- Fix: the "Keep holding to send ..." hint threw an error in P4.1 (it still read a removed import). It now also describes trained gestures' actions.
- Testing: `npm run e2e` gains 22 Phase 4 checks (79 in all): recording at ~30 samples/s, replay at 2×, interrupting a replay, rename, reload, export/delete/import, a bad file, training two gestures with the simulator, triggering their actions, built-in gestures still working, the accuracy report, and deleting a mapped motion.
- Docs: README, `docs/ARCHITECTURE.md`, `docs/TESTING.md`, `docs/LEARNING.md` (Phase 4) and `src/core/types.md` updated.

### Phase 3: Pick-and-place challenge
- P3.1: Blocks and grabbing. A low table and three blocks (red, green, blue) appear with the arm (`src/scene/blocks.js`); their positions and rules live in the pure `src/core/stacking.js`. When the arm's grip closes with the gripper point within 0.25 of a block's top, that block attaches to the gripper and turns with the base; only one block is held at a time. The grip uses its own hysteresis (close above 0.6, open below 0.4) and follows the arm's eased grip, so grabbing also works with the joint sliders and in AUTO. The block that would be grabbed glows, the fingers stop at the sides of a held block, and grabs and drops are logged. Selecting the arm now points the camera at the table. The AUTO path was adjusted to line up with the starting blocks.
- P3.2: Drop and stack. A released block falls straight down (animated) until it rests on the table, the floor past the table's edge, or the highest block under its footprint. It lands square to the table, and snaps exactly on top when it covers more than 60% of the block below. A block with another on top can't be grabbed, and a held block can't be pushed into the table or another block. `isOneStack` checks for a finished tower. Tests cover table drops, block drops, partial overlap, and the AUTO demo stacking red on blue.
- P3.3: Challenge mode (`src/core/challenge.js`). A **Stacking challenge** panel (arm only) with **Start**, which resets the blocks and starts a timer, and **Reset blocks**. The run is won when all three blocks form one tower and nothing is held; the time is shown and the best time is saved in `localStorage` under `handpilot.challenge.v1` (separate from settings, so **Reset to defaults** keeps it). A timer also shows on the stage during a run.
- P3.4: README slots for the demo GIF and 30-second video, with recording notes in `docs/media/README.md`. The media themselves are still to be recorded.
- Fix: with the camera the arm barely moved sideways, because the whole image width mapped to the workspace but your palm can't get near the image edge without your hand leaving the frame, and the box only let the base turn about ±50°. Added a **Hand sensitivity** slider (1.0–2.5, default 1.6, saved in settings) that stretches hand movement around the centre of the image, so the middle ~60% of the picture covers the whole box. The workspace is wider (x ±2.0, base turns up to about ±60°) and the table with it. The simulator is unaffected.
- Humanoid feels more responsive: **Hand sensitivity** (saved as `handGain`; a value saved as `armGain` is kept) now also stretches the humanoid's body turn, so it reaches its full turn without your hand leaving the picture, and the slider shows for both robots. In MANUAL the humanoid now eases 70% of the way to your fingers each frame instead of 35%, once it has been in MANUAL for 0.6 s; mode changes still use the gentle ease. The One Euro filter still removes the jitter.
- Testing: `npm run e2e` (`tests/e2e/checklist.mjs`, with `playwright@1.48.2` as a dev dependency) runs the manual checklist in headless Chromium against a server it starts itself: 57 checks covering gestures, settings, the arm, blocks, the challenge, a fake webcam, blocked storage and phone width. Not part of `npm test`, which stays fast and offline.
- Docs: README, `docs/ARCHITECTURE.md`, `docs/TESTING.md`, `docs/LEARNING.md` (Phase 3) and `src/core/types.md` updated.

### Phase 2: Robot arm teleoperation
- P2.1: Robot arm model (`src/scene/arm.js`): base yaw, shoulder, elbow and wrist pitch, and a two-finger gripper, built from nested Groups. Its lengths, joint limits and parked pose live in `src/core/armSpec.js` so the IK solver (P2.3) can share them. A **Humanoid / Arm** switch in the header picks the robot and is saved in settings. With the arm selected, an **Arm joints** debug panel drives each joint, and **Park arm** resets it.
- P2.2: Hand position to a 3D target (`src/core/workspace.js`): palm x (mirrored) and y map across a workspace box in front of the arm, and palm width in the image gives depth (wider = closer to the camera = reach in toward the base). The box is drawn faintly and the target shows as a small sphere. The simulator gains **Height** and **Reach** sliders; **Turn** moves the target left and right.
- P2.3: Inverse kinematics (`src/core/ik.js`): `solveIK` turns the base toward the target, then solves the shoulder and elbow with the law of cosines (elbow-up) and sets the wrist to keep the gripper level. It aims the gripper point (`ARM.tool` past the wrist), clamps every joint to its limits and reports `reachable: false` when it had to stretch or clamp. `forwardKinematics` goes the other way. The arm now follows the target; the sphere turns red when it is out of reach. The joint panel shows the live IK angles, and **Drive joints with the sliders** switches back to manual joint control. The workspace box was tightened so almost all of it is reachable, and selecting the arm swings the camera to a three-quarter view.
- P2.4: Pinch to grab (`src/core/pinch.js`). A pinch latch with hysteresis closes the gripper when pinch drops below 0.35 and opens it only above 0.5, so a noisy value near either threshold can't make it chatter. A missing reading keeps the last state. The fingers ease open and shut, and each grab and release is logged. The simulator gains a **Pinch** slider.
- P2.5: Agent modes for the arm (`src/core/armMotion.js`). MANUAL follows the hand target and pinch, HOLD freezes every joint, AUTO runs a looping pick-and-place demo (left to right, gripper closing and opening on the way), IDLE parks the arm, and GREET waves the gripper. The agent itself is unchanged; it just gets an optional `actText` so its log, the HUD and the agent panel describe what the arm is doing. The finger channel labels change with the robot too.
- Docs: README, `docs/ARCHITECTURE.md`, `docs/TESTING.md` and `docs/LEARNING.md` (Phase 2) updated.
- Fix: on screens narrower than about 500px the 3D stage overflowed the page, because its 320px min-height plus 16:11 aspect ratio forced a 465px min width. Narrow screens now use a 4:5 stage with no min-height.

### Phase 1: Pro hand tracking
- P1.1: Camera switched from the legacy `@mediapipe/hands` script to the MediaPipe Gesture Recognizer (`@mediapipe/tasks-vision@0.10.35`), on the GPU with a CPU fallback. Recognition only runs when the video has a new frame. HandFrames now carry world landmarks, handedness (shown as a chip on the stage), palm position and depth, pinch, and MediaPipe's built-in gesture (shown under the gesture name). Confident built-in gestures drive the agent; the rule-based classifier is the fallback and still drives the simulator.
- P1.2: One Euro filter (`src/core/filters.js`) with one filter per finger bend plus palm x/y/z and pinch, applied to both camera and simulator input. The Smoothing slider is replaced by **Min cutoff** and **Beta** sliders (defaults 1.0 and 1.0, tuned for 0–1 signals; the textbook beta of 0.01 is for pixel units and lagged about 12 frames here). The pose blend is now a fixed light ease. `smoothingAlpha` was removed from `core/agent.js`.
- P1.3: Settings (calibration, filter tuning, selected robot, gesture mappings) saved to `localStorage` under one versioned key, `handpilot.settings.v1`, through `src/core/settings.js`. Storage is passed in, every access is wrapped in try/catch, and each field is validated on load so one bad value never wipes the rest. A calibration saved by the Phase 0 app is migrated on first run. Added a **Reset to defaults** button. The robot and gesture-mapping fields are stored now and become editable in Phases 2 and 4.
- P1.4: Performance HUD on the stage: render FPS, tracking FPS and average milliseconds per recognition call, refreshed once a second by a small `PerfMeter` (`src/core/perf.js`).
- P1.5 (optional, Web Worker recognition) was skipped.
- Docs: README, `docs/ARCHITECTURE.md`, `docs/TESTING.md` and `docs/LEARNING.md` (Phase 1) updated.
